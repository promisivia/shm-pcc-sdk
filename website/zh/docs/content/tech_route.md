# 技术路线（Tech Route）

SHM-PCC-SDK 面向“共享内存/CXL 平台上的系统开发”。相比传统的“把内存映射出来再手写协议/容器/同步”，SDK 选择把**数据结构（Data Structures）**作为核心抽象：让应用用 `map/set/tree/hash/...` 来表达共享状态，然后围绕这些有语义的数据构建内存管理、并发控制与通信能力。

## 为什么用数据结构做核心

共享内存平台上的关键困难往往集中在“正确性 + 生命周期 + 共享语义”：

- **正确性**：部分缓存一致性、跨 NUMA/跨机可见性、并发访问等，会让“裸指针 + 自己加锁”的成本迅速升高。
- **生命周期**：共享内存里的对象可能跨线程/进程/机器存活；一旦发生部分失效（Partial Failure）或异常退出，容易出现“分配了但没人能再访问”的泄漏。
- **共享语义**：很多系统通信传递的不是字节流，而是“对某个 key 的读写/对某段范围的扫描/对某个对象的引用”。

把共享状态收敛到一组标准数据结构后，SDK 才能在同一套抽象下做一致的优化与约束（例如：统一的分配方式、统一的可达性管理入口、统一的跨线程/跨机访问封装）。

## 当前实现的主线

你可以按下面顺序理解/使用仓库代码（从“可落地使用”到“持续演进”）：

1. **共享内存分配与类型（Allocator / CXL types）**
   - `shm-lib/include/shm/**`：内存映射、`cacheable` 分配器、`CXLAllocator`、`cxl_vector/cxl_string` 等基础类型。
2. **数据结构（DS）**
   - `ds/**`：索引/哈希/树等实现；`tests/YCSB-C/` 里的 `db/*_db.*` 提供对这些数据结构的统一适配入口。
3. **通信/协作（Msg / Connection）**
   - `shm-lib/include/msg/**`：共享内存消息队列与分发/收集逻辑（用于把“请求/任务”在多线程/多进程间传递）。
   - `shm-lib/include/connection/**`：多机启动与 follower 编排（以 YCSB-C 的 master/follower 逻辑为主要参考）。

## 后续演进方向（Roadmap 粗粒度）

- **并发与同步**：面向平台特征的 lock/lock-free/事务化能力完善。
- **数据结构扩展**：补齐更通用的 `map/list` 等容器形态，并沉淀“共享内存下的使用约束”。
- **增强通信语义**：让通信层更多理解“对数据结构的操作意图”，而不仅是字节消息。
- **内存管理/回收**：利用“数据结构有根（root）”这一事实，把不可达对象视为泄漏候选，逐步补齐可控的回收策略。
