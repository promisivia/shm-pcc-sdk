# 系统架构（Architecture）

SHM-PCC-SDK 的目标是把“共享内存/CXL 平台上的系统开发”拆成可复用的组件层：**数据结构作为核心抽象**，围绕它提供内存管理、并发控制、以及通信/RPC 等能力。

这套思路背后的直觉是：应用最终要操作的是“有语义的数据”（map/set/tree/graph），而不是裸内存块。把数据结构做成核心层，可以让上层系统以更低成本获得一致的性能与正确性保障，并为后续的内存回收、RPC 语义增强等留出接口。

## 分层视图（建议的理解方式）

1. **应用层（Apps / Systems）**
   - 例如：YCSB、数据库索引、图计算、缓存服务等
2. **组件层（Components）**
   - 数据结构（Hash/Tree/Map/List…）
   - RPC/通信（基于数据结构语义做传输/共享）
   - 工具与运行时（线程池、任务队列、监控/统计等）
3. **平台层（Platform）**
   - 共享内存/CXL 设备与系统特性（部分缓存一致性、部分失效、跨机共享等）

## 典型数据流（一个最小闭环）

- 应用把关键状态放入 SDK 提供的数据结构中（作为共享状态的“根”）
- 其它线程/进程/机器读取或更新这些共享状态
- 组件层负责提供一致的并发访问与资源管理策略

## 现状与边界

SDK 中部分组件仍在持续实现中。文档会用“状态标记（已实现/进行中/计划）”明确当前可用范围，避免你误用未完成的接口。
